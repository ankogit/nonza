# Rust + Tauri Learning Guide (для быстрого вката)

Этот док — “дорожная карта” как прокачаться по Rust и Tauri до уровня, когда ты можешь:
- чинить проблемы вида “не работает глобальный шоткат / IPC / разрешения”
- безопасно рефакторить backend
- добавлять новый функционал без развала архитектуры

Док ориентирован на практику в конкретном проекте `apps/meet/src-tauri`.

---

## 0) Что тебе нужно понять в голове (mental model)

В Tauri всегда есть два мира:
- **Frontend (WebView)**: JS/TS код, UI, DOM-ивенты, подписки на события.
- **Backend (Rust)**: нативные возможности (сеть, файлы, OS-интеграции), обработка `#[tauri::command]`, состояние через `State`, IPC через `invoke` и события.

Типовой поток действий:
1) Frontend делает `invoke("command_name", payload)`
2) Rust выполняет команду/логикку
3) Rust отправляет событие в UI через `emit_to(...)`
4) Frontend подписывается и реагирует

Ключевая идея: **backend — источник правды** для системных действий, а frontend — диспетчер UI.

## 1) Rust: что учить в правильном порядке

Тебе важны не “все фичи языка”, а база, без которой Tauri-проекты ломаются:

### 1.1 Владение (ownership) и заимствования (borrowing)
- почему `Arc<T>` нужен для shared state между потоками
- разница `&T` / `T` / `Arc<T>`

Практика: в проекте ты постоянно встречаешь `Arc` в контекстах listener’ов и shared state.

### 1.2 Потоки и синхронизация
- `thread::spawn`
- `Mutex<T>` для мутабельного состояния
- `AtomicBool/AtomicUsize` для простых флагов

Практика: OS-listener часто заводит отдельный поток и передает туда флаг/handle.

### 1.3 Ошибки и результаты
- `Result<T, E>`, распространение ошибок через `?`
- где уместно логировать и где уместно возвращать `Err`

Практика: Tauri-команды возвращают `Result<(), String>` или `Result<_, tauri::Error>`.

### 1.4 Коллбеки и захват переменных (move/capture)
- почему в замыканиях может “уводить” переменную
- как чинить через `.clone()` / `let x_for_callback = x.clone()`

Практика: очень часто всплывает в OS-хуках и event tap callback’ах.

### 1.5 FFI (когда “лезешь в систему”)
- минимально: как правильно объявлять и использовать типы из `core-graphics` / `windows-sys`
- как читать сигнатуры: что где unsafe

Практика: `mouse_listener/macos.rs` и `mouse_listener/windows.rs` — это твои лучшие “живые” примеры.

## 2) Tauri: что учить “от и до”

### 2.1 `tauri::Builder`, `setup`, `invoke_handler`
- `setup(|app| ...)` — место для инициализации: plugins, state, запуск фонов, регистрация меню/слушателей.
- `invoke_handler(...)` — список команд, которые frontend может дергать.

В проекте:
- `src-tauri/src/lib.rs` — оркестрация
- `src-tauri/src/shortcuts.rs` — команды/меню/регистрация хоткеев

### 2.2 Команды: `#[tauri::command]`
- что возвращает команда (обычно `Result<_, String>` для ошибок)
- как правильно именовать команду и вызывать её из frontend

Практика: открой `src-tauri/src/shortcuts.rs` и посмотри команды:
- `set_shortcut_bindings`
- `reregister_global_shortcuts`
- `trigger_meeting_shortcut`

### 2.3 Состояние: `app.manage(...)` и `app.state::<T>()`
- где хранить shared state
- когда удобнее `Mutex<String>`, а когда `AtomicBool`

В проекте:
- `ShortcutBindings` хранит отдельно `*_keyboard` и `*_mouse`
- `mouse_listener/mod.rs` хранит `active`-флаг

### 2.4 События: `emit_to` / event bus в UI
- Rust отправляет событие в конкретный окно/контекст
- UI ловит и маршрутизирует на внутренние обработчики

В проекте:
- команда `trigger_meeting_shortcut` шлёт `meeting-shortcut`

## 3) Plugins: “как мыслить”

Три типа плагинов встречаются в реальных проектах:
- **интеграции уровня Tauri** (навигация, openers)
- **глобальные хуки** (вроде global shortcut)
- **инфраструктура** (log, updater)

Важно:
- scope `#[cfg(desktop)]` часто нужен, чтобы backend компилился под нужные платформы.
- большинство проблем с глобальными вещами упираются в пермишены/политику ОС.

---

## 4) Capabilities/Permissions: почему “не работает” = почти всегда разрешения

В Tauri v2 разрешения задаются в capabilities (`default.json`, `desktop.json` и т.п. — в зависимости от проекта).

Что запомнить:
- `global-shortcut:*` нужен, чтобы плагин реально мог регистрировать хоткеи.
- команды могут требовать дополнительные permissions (если проект так настроен).

Практика:
- когда команда/плагин падает, смотри ошибки прав в логах Tauri.

---

## 5) Дебаг-стратегия (чтобы не гадать)

У тебя должен быть один шаблон мыслей:
1) **Rust side**: команду вызвали? state обновили? listener поставился?
2) **IPC side**: Rust эмитнул событие в правильное окно (`emit_to("main", ...)`)?
3) **Frontend side**: подписка стоит? обработчик реально вызывается?
4) **OS side**: permissions? event type? hook реально ловит?

Для этого в проекте уже есть полезные логи (пример:
- `[global-shortcut] ...`
- `[mouse-listener] ...`
- `[mouse-shortcut] invoke ...`)

## 6) Мини-курс (практика без воды): 3 “занятия”

### Занятие 1: пройти по коду end-to-end
1) `src-tauri/src/lib.rs`
2) `src-tauri/src/shortcuts.rs`
3) `src-tauri/src/mouse_listener/*`
4) `src/shared/lib/useTauriGlobalShortcuts.ts`

Твоя цель: понять, кто за что отвечает, и где именно ловятся события.

### Занятие 2: добавить диагностический лог на реальный кейс
- Например: при входе в `set_shortcut_bindings` логировать:
  - исходные строки from frontend
  - что получилось после нормализации `*_keyboard` и `*_mouse`

### Занятие 3: отладить “не ставится” или “не приходит”
- macOS: `CGEventTap install failed` чаще всего упирается в permissions.
- Windows: если хук “не живёт”, обычно проблему видно в логе установки/жизненного цикла callback’а.

## 7) Быстрые ориентиры по репозиторию

Для твоего текущего контекста (где обычно “болит”):
- `src-tauri/src/shortcuts.rs` — хоткеи/меню/команды
